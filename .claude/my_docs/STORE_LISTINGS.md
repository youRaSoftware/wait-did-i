### 6.2 App Privacy / Data Collection

**Top-level вопрос:** `No, we do not collect data from this app` ✅

**Обоснование:** в 1.0 нет аккаунта, облака, аналитики и крэш-репортинга. Всё (списки,
отметки, фото) хранится **только на устройстве** и не передаётся разработчику или третьим
сторонам. По правилам Apple данные, которые не покидают устройство, **не считаются
собранными** → Privacy Nutrition Label = **Data Not Collected**.

> 🔁 Когда/если добавим аналитику, crash-репортинг или облачный бэкап — пересмотреть эту
> секцию и заполнить соответствующие типы данных. Сейчас — ничего не отмечать.

**Permissions (это НЕ сбор данных, а доступ) — нужны usage strings в Info.plist:**

| Permission | Ключ Info.plist | Зачем |
|---|---|---|
| Камера | `NSCameraUsageDescription` | Сделать фото-подтверждение пункта |
| Фото (если сохраняем/выбираем) | `NSPhotoLibraryAddUsageDescription` / `NSPhotoLibraryUsageDescription` | Сохранить/приложить фото |
| Face ID | `NSFaceIDUsageDescription` | Блокировка входа в приложение |
| Уведомления | runtime-запрос | Одно напоминание по времени |

> Тексты usage strings — спокойные и утилитарные, без слов «тревога». См. APPLE_REVIEW_FIXES.md.

### 6.3 Accessibility Nutrition Labels

**Device:** ✅ iPhone (только; см. 6.4).

Дешёвый честный путь для 1.0 — на главный вопрос ответить **No** (секция пропускается,
в листинге просто нет accessibility-меток). Клеймить фичи (Dark Interface, Larger Text,
VoiceOver) только после реального аудита кастомных виджетов с `Semantics`.

### 6.4 Supported Devices

**Подача — iPhone only** (портретный layout, под iPad не оптимизирован). В Xcode → Runner →
General → Supported Destinations убрать iPad. После релиза, если зайдёт — добавить iPad
отдельным апдейтом. Альтернатива без работы: «iPhone (Designed for iPad)» — Apple сама
разрешит ставить на iPad в scaled-режиме.
