# Claude Code Skills — Руководство по использованию (Wait, Did I?)

## Что такое Skills?

Skills — кастомные команды для Claude Code с подробными инструкциями по созданию кода
в нашем проекте. Их можно вызывать явно (`/имя`) или Claude подхватывает их **автоматически**,
когда формулировка задачи совпадает с описанием скилла.

> ⚠️ **Статус миграции.** Скиллы перенесены из другого проекта и пока несут его следы
> (упоминания Firestore / Cloud Functions / доменных виджетов). UI-референс
> (`shared/ui_reference.md`) уже переписан под нас. Полная адаптация самих скиллов под нашу
> архитектуру (local-first, без бэкенда) — отдельная задача. Учитывай это (см. колонку
> «Применимость» ниже).

## Доступные Skills

| Команда | Когда использовать | Применимость к нам |
|---|---|---|
| `/create-feature-ui` | Нужны экраны с мок-данными, бэкенд/хранилище не готово | ✅ Подходит. Создаёт Model (с моками), State, Cubit, Screen, Form, Route |
| `/create-feature-full` | Полная фича с данными | ⚠️ Скилл заточен под **Firestore + Cloud Functions**, которых у нас НЕТ (мы local-first, Hive). Пока не адаптирован — для данных используй `create-feature-ui` + руками подключи локальный репозиторий по `shared/ui_reference.md` §4.6 |
| `/create-widget` | Переиспользуемый UI-компонент в `core_ui/lib/widgets/` | ✅ Подходит. Читает `shared/ui_reference.md` (наши токены/стиль) |
| `/analyze-feature` | Нужен контекст по существующей фиче | ✅ Подходит. Пишет документ в `.claude/my_docs/{feature}.md` |
| `/audit-section` | Аудит раздела перед продом | ⚠️ Частично: вертикальный анализ описан под Firestore-слой; горизонтальный анализ применим. Сверяйся с `shared/ui_reference.md` (у нас нет `MascotMessage` и доменных виджетов) |
| `/llm-council` | Спорное решение, обкатать с разных сторон | ✅ Generic, не зависит от проекта |

## Как использовать

### Способ 1: Явный вызов (slash-команда)

```
/create-feature-ui
```
Claude загрузит скилл и спросит детали. Или сразу с аргументами:
```
/analyze-feature onboarding — нужен полный контекст по фиче онбординга
```

### Способ 2: Авто-триггер (просто опишите задачу)

```
Создай экраны для фичи «Детали списка» с мок-данными: экран списка пунктов и экран
создания списка.
```
Claude увидит «экраны» + «мок-данные» → `create-feature-ui`.

```
Напомни, что у нас сделано на главном экране? Нужен контекст по features/lib/home/
```
Claude увидит «нужен контекст по фиче» → `analyze-feature`.

### Способ 3: Явная ссылка в тексте

Если авто-триггер не сработал — упомяните скилл в запросе:
```
Используя create-widget, сделай карточку пункта чек-листа ChecklistItemTile.
```

## Что давать Claude при вызове

### create-feature-ui
- Название фичи, описание (что делает), список экранов, (опц.) ссылку на дизайн.

### create-feature-full ⚠️
- См. оговорку выше. У нас нет Firestore/Cloud Functions — скилл в текущем виде не применим
  напрямую. Для данных: моки через `create-feature-ui`, затем локальный репозиторий руками
  (провайдер → репозиторий → маппер → модель, DI в `data/lib/di/data_di.dart`).

### create-widget
- Название виджета, категория (buttons / input_fields / tabs / modals / scaffold / toast / misc),
  описание поведения и вариантов. Должен соблюдать плоский стиль (без glow/blur/градиентов).

### analyze-feature
- Название фичи или путь в `features/lib/`; (опц.) путь сохранения (по умолчанию `.claude/my_docs/{feature}.md`).

### audit-section
- Название раздела, путь к фиче, пути к документации (.md/.pdf), (опц.) путь для результатов.

### llm-council
- Вопрос/решение с контекстом: какие варианты, какие ставки, что пробовали.

## Примеры реальных запросов

### UI фича с моками
```
/create-feature-ui

Фича: ChecklistDetail (Детали списка)
Описание: пользователь открывает список и отмечает пункты; может добавить пункт
Экраны:
- ChecklistDetailScreen — пункты с тремя состояниями (отмечено / ещё нет / стоит глянуть)
```

### Виджет
```
/create-widget

Виджет: ChecklistItemTile
Категория: misc
Описание: строка пункта чек-листа — кружок состояния (зелёная галочка / пунктирный пустой /
жёлтый колокольчик), заголовок, опциональная миниатюра фото-подтверждения и таймстемп
```

### Анализ фичи
```
/analyze-feature

Фича: Onboarding
Путь: features/lib/onboarding/
Результат: .claude/my_docs/onboarding_feature.md
```

### Совет AI-советников
```
/llm-council

Хранить фото в Hive (base64/bytes) или в файловой системе приложения с путём в Hive?
Контекст: фото авто-удаляются через 30 дней, всё локально, важна приватность и размер БД.
```

## Структура файлов

```
.claude/
├── changelog/
│   └── CHANGELOG.md            ← user-facing изменения (релиз-ноты + промо-тексты)
├── my_docs/                    ← проектные доки + выводы analyze/audit
│   ├── ROADMAP.md
│   ├── STORE_LISTINGS.md
│   ├── STORE_CONTENT_BRIEF.md
│   └── APPLE_REVIEW_FIXES.md
├── shared/
│   └── ui_reference.md         ← UI/архитектура — источник правды для create-* скиллов
├── skills/
│   ├── create-feature-ui/SKILL.md   (+ evals/)
│   ├── create-feature-full/SKILL.md (+ evals/)
│   ├── create-widget/SKILL.md       (+ evals/)
│   ├── analyze-feature/SKILL.md
│   ├── audit-section/SKILL.md
│   └── llm-council/SKILL.md
├── plans/                      ← (пусто) под планы конкретных задач; основной план — корневой PLAN.md
├── SKILLS_GUIDE.md             ← этот файл
└── settings.json
```

> Источник правды по продукту — корневой `PLAN.md`. Лог изменений по файлам — `CLAUDE_CHANGES.md`.

## FAQ

**Q: Claude вызвал не тот скилл?**
A: Уточните запрос или вызовите нужный явно через slash-команду.

**Q: Можно ли редактировать skills?**
A: Да, это `.md` файлы. Правьте `SKILL.md` в нужной папке. У `create-*` скиллов есть `evals/`.

**Q: Как добавить новый skill?**
A: Создайте `.claude/skills/{name}/SKILL.md` с frontmatter (`name`, `description`) и содержимым.

**Q: Откуда скиллы знают про дизайн-систему?**
A: `create-feature-ui`, `create-feature-full` и `create-widget` перед генерацией обязаны прочитать
`.claude/shared/ui_reference.md` — источник правды по нашим токенам, виджетам и стилю кода.
